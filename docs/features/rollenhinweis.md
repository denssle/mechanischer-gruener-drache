# Rollenhinweis

- Zweck: Auf dem Server gibt es einen Kanal, in dem Leute landen, die sich (noch) keine Rolle geholt haben. Schreibt dort jemand **ohne jede Rolle**, antwortet der Bot **einmal** mit dem Hinweis, dass man sich eine Rolle holen kann, um alles zu sehen und mitzumachen (`ROLLENHINWEIS_TEXT` in `rollenhinweis.handler.ts`).
- **Warum keine ephemere Antwort:** „Nur du kannst das sehen" gibt es in Discord **nur** als Antwort auf Interactions (Slash-Command, Button, Modal, Kontextmenü) – auf eine normale Chatnachricht kann kein Bot ephemer antworten, das gibt die API nicht her. Zur Wahl standen DM (privat, aber bei geschlossenen DMs nichts), selbstlöschende Antwort oder bleibende Antwort; gewählt wurde am 2026-10-22 die **bleibende Antwort** (`message.reply`, User-Entscheidung).
- **„Ohne Rolle" heißt gar keine Rolle.** `@everyone` steckt in jedem `member.roles.cache` (ID = Guild-ID) und zählt nicht; sobald irgendeine andere Rolle da ist, schweigt der Bot. Bewusst nicht auf eine bestimmte Rolle geprüft.
- **Einmal pro Person, für immer** (User-Entscheidung, kein Tages-Cooldown): `ROLLENHINWEIS:HINGEWIESEN` ist ein Set der User-IDs. Eingetragen wird **vor** der Antwort per `SADD` – dessen Rückgabe sagt in einem Schritt, ob die Person neu war, damit zwei schnell hintereinander geschickte Nachrichten nicht zwei Hinweise auslösen (dafür gibt `redisService.addToSet` seit diesem Feature `boolean` zurück). Scheitert die Antwort, wird der Eintrag wieder entfernt (`vergiss`), sonst wäre die Person vermerkt, ohne je etwas gesehen zu haben. Verliert jemand später alle Rollen wieder, kommt **kein** zweiter Hinweis.
- **Kanal über `/config`** (Bereich „Rollenhinweis", eine Zeile in `KANAL_SERVICES`), dort steht auch der Antworttext zur Ansicht. Ohne Kanal passiert nichts. Wie alle Kanal-Felder ist er Pflicht, sobald gesetzt – **abschalten** lässt sich das Feature über `/config` derzeit nicht (nur umhängen); falls nötig: `DEL ROLLENHINWEIS:CHANNEL`. `/diagnose` prüft den Kanal mit.
- **Link auf den Rollen-Kanal (seit 2026-11-07, optional):** `/rollenbutton` speichert bewusst nichts, der Bot weiß also nicht, wo der Button liegt. Deshalb ein zweites Kanal-Feld auf `/config` (`rollenhinweis-rollenkanal`, Key `ROLLENHINWEIS:ROLLENKANAL`). Ist es gesetzt, wird aus „Hol dir eine Rolle" per `rollenhinweisText()` „Hol dir in <#…> eine Rolle". Ohne Feld bleibt der Text generisch. Der Kanal muss für Leute ohne Rolle sichtbar sein, sonst zeigt Discord den Link als unbekannten Kanal. Das meldet `/diagnose` seit 2026-11-07. `/diagnose` prüft das Feld, zeigt es leer aber nur als ℹ️ (optional).
- Verkabelung: eigene `MessageCreate`-Registrierung in `index.ts` (mit `.catch()`, siehe Stolperfallen). Der Handler importiert `client` nicht.
- Der Text ist fest im Code, nicht auf `/config` editierbar – bei Bedarf `ROLLENHINWEIS_TEXT` anpassen. Er trägt keinen fremden Text, deshalb kein `allowedMentions` nötig; die Antwort pingt die Person (Reply-Standard), damit sie den Hinweis auch bemerkt.

## Willkommensgruß (seit 2026-11-07)

- Anlass: 87 von 225 Mitgliedern hatten die Hauptrolle nicht, und laut Discords Vorschau „Mitglieder entfernen" waren nur 38 davon länger als 7 Tage weg. Das sind also keine Karteileichen. Der Hinweis oben erreicht aber nur, wer im Kanal **schreibt**, wer still mitliest, erfuhr nie etwas.
- `handleBeitritt` (`GuildMemberAdd`, eigene Registrierung in `index.ts`) schreibt in den Kanal aus `/config` (`rollenhinweis-willkommen`, Key `ROLLENHINWEIS:WILLKOMMENSKANAL`) einen festen Text samt Ping und nutzt denselben Link auf den Rollen-Kanal. Ohne Kanal passiert nichts, Bots werden nicht begrüßt.
- **Der Ping braucht `allowedMentions: {users: [id]}`**, sonst schluckt ihn die Voreinstellung am Client.
- **Markiert bewusst nicht als „hingewiesen":** Wer den Gruß übersieht und später im Hinweis-Kanal schreibt, soll die Antwort noch bekommen. Die ist dann die zweite Chance, im passenden Moment.
- **Kein Merker gegen Wiederkehrer:** Wer geht und wiederkommt, wird erneut begrüßt. Das ist so gewollt und bleibt selten.
- **Hauptrolle** (`rollenhinweis-hauptrolle`, Key `ROLLENHINWEIS:HAUPTROLLE`, optional): gilt nur für die Zählung in `/diagnose`. Der Hinweis selbst prüft weiter auf „gar keine Rolle", siehe oben.
